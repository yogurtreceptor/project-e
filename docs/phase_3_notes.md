# Phase 3 Notes

This is an informal collection point for potential Phase 3 directions, user assertions and open questions. It is deliberately not a phase specification, roadmap commitment, implementation plan or implementation authority. Entries may be revised, rejected, promoted into a later authorised scope, or removed as understanding improves.

Phase 2 remains the active implementation workspace until a formal next phase is deliberately defined. The [roadmap](../ROADMAP.md) retains its directional Phase 3 AI-assisted-platform heading; these notes do not narrow, expand or sequence that direction.

## How to use this document

- Record an idea in plain language, with context and uncertainty where useful.
- Keep proposals distinct from agreed product behaviour.
- Link an item to canonical records, local-first constraints, privacy or approval boundaries when relevant.
- Do not treat an entry as permission to implement it.

## Notes

### Journey planning — deferred from Phase 2

Explore a local-first journey-planning proof slice between canonical Locations, optionally in relation to an arrival Event. The preferred starting direction is locally held OpenStreetMap data and static public-transport data, with a user-approved travel Event using the existing Calendar and reminder workflow.

Live transit, traffic and any other network-derived information would be optional, replaceable enrichment rather than a core dependency. Open questions include the useful minimum journey-planning workflow, offline-data size and update expectations, and whether an optional local routing runtime fits the platform's conservative-dependency model.
